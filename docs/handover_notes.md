# Handover

## สถานะล่าสุด
บน branch `dev`: ตู้เย็น, หน้าหลัก (+ บันทึกค่ากิน, แผนกิน), **แดชบอร์ด** (ADR-010) และการบันทึกข้อมูลในเครื่อง (ADR-009) เสร็จ ตรวจบน Chrome แล้ว; เหลือแท็บ **สุ่มเมนู** และ **สแกน** ที่ยังเป็น placeholder
เทสต์: แอป 112 ผ่าน, core 64 ผ่าน, analyze สะอาด

## ทำแล้วรอบล่าสุด (แดชบอร์ด)
- งบรอบ / วันเงินเข้า / ราคาซื้อกิน แก้ได้ด้วย stepper (กดค้างเร่งได้) และบันทึกถาวร
- เส้นเวลารอบ (อยู่ในงบ / เกิน / ไม่ได้บันทึก / วันนี้ / อนาคต), ตาราง "เงินที่เหลือซื้ออะไรได้", เมนูที่ทำบ่อย
- เหรียญ 5 อัน (คงแนวคิดเดิม ไม่มีอีโมจิ) คำนวณจากการเล่นประวัติซ้ำ: ใช้/ทิ้ง, ทำกิน, รายจ่าย — undo แล้วเหรียญถอยตาม
- `trackingSince`: วันก่อนเปิดแอปครั้งแรกไม่นับเป็น "ไม่ทิ้งของ"

## ค้างอยู่ / ปัญหา
- วันที่ไม่ได้บันทึกรายจ่ายนับเป็น "อยู่ในงบ" (ข้อจำกัดใน ADR-010) — จะแก้ได้ด้วย "ปิดวันตอนค่ำ"
- ข้อมูลตัวอย่าง (ใช้ 180-200 บาท/วัน) ทำให้แดชบอร์ดแดงเกือบทั้งรอบ — ชวนท้อสำหรับเดโม
- ฐานสูตร 10 เมนู + ค่าประมาณการ → วุฒิตรวจ/เพิ่ม
- ยังไม่ทดสอบบนมือถือจริง (รอ Android Studio — ขั้นตอนใน `engineering/tooling_setup.md`); Windows Developer Mode ยังปิด (กระทบเฉพาะ build Windows desktop)
- ผู้ก่อตั้งจะวางไฟล์เดิม (Unity / เดโม HTML / ui_design_prompt) → เทียบ ADR-002 และชื่อเหรียญ

## ขั้นต่อไป (เสนอ)
1. แท็บสุ่มเมนู: วงล้อ 3 แกน หยุดเหลื่อม, ล็อกแกน, ทำเอง/สั่งข้างนอก, sheet ผล (ใช้ `IngredientSlotMachine` ที่มีอยู่แล้วใน core) → ต่อกับ "ทำแล้ว" แบบเดียวกับแผนกิน
2. แท็บสแกน (หลังมี Android + ADR เลือกแพ็กเกจกล้อง/ML Kit)
3. รอผู้ก่อตั้งอนุมัติ: รายการซื้อของ, แจ้งเตือนเช้า, ปิดวันตอนค่ำ
