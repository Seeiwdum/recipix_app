# Handover

## สถานะล่าสุด
บน branch `dev`: แท็บตู้เย็น + หน้าหลัก + บันทึกค่ากิน + แผนกิน + **บันทึกข้อมูลในเครื่อง** (ADR-009) เสร็จ; ปิด/เปิดแอปข้อมูลยังอยู่ (ตรวจบน Chrome แล้ว); สแกน / สุ่มเมนู / แดชบอร์ดยังเป็น placeholder
เทสต์: แอป 95 ผ่าน, core 63 ผ่าน, analyze สะอาด

## ทำแล้วรอบล่าสุด (บันทึกในเครื่อง)
- shared_preferences + JSON 2 ก้อน (`recipix.fridge.v1`, `recipix.budget.v1`) โหลดก่อนเฟรมแรก บันทึกทุกครั้งที่เปลี่ยน + ตอนแอปถูกพัก
- ข้อมูลเสีย → สำรองไว้ที่ `<key>.corrupt.<เวลา>` ก่อนเริ่มใหม่ ไม่ทับเงียบ
- เปิดครั้งแรกยังเติมข้อมูลตัวอย่าง (เพราะยังเพิ่มของเองไม่ได้) — เมื่อมีแท็บสแกนแล้วควรเริ่มจากตู้ว่าง (ผู้ก่อตั้งตัดสิน)

## ทำแล้วรอบก่อน
- `BudgetLedger` (core): งบทั้งรอบ − รายจ่ายในรอบ, งบวันนี้คงที่ตั้งแต่เช้า, นับมื้อกินข้างนอกวันนี้
- หน้าหลัก: ปุ่ม "บันทึกค่ากิน" → sheet (จำนวน, ปุ่มลัด, หมวด, รายการวันนี้ลบได้), "ใช้ไป · เหลือ" / "เกินงบวันนี้", ยอดขาดขยับทันที
- `MealPlanner` (core): วางแผนทุกมื้อถึงเงินเข้า ใช้ของในตู้ก่อน (ตามปริมาณ + วันหมดอายุจริง) ที่เหลือซื้อกิน, ยอดขาดตามแผน, รายการของที่จะเสีย
- หน้าแผน `/home/plan`, แถว "มื้อถัดไป" บนหน้าหลัก, sheet ทำกิน → ตัดของจริงจากตู้ + เลิกทำ
- แก้: toast เลิกทำไม่หายเอง (Flutter 3.47) → หายใน 5 วินาทีแล้ว

## ค้างอยู่ / ปัญหา
- Windows Developer Mode ยังปิด (กระทบเฉพาะ build Windows desktop) — ดู tooling_setup
- งบรอบ/วันเงินเข้า/ราคาต่อมื้อยังแก้ในแอปไม่ได้ (ตั้งใจให้อยู่ในแดชบอร์ด)
- ฐานสูตรมี 10 เมนู + ค่าประมาณการ → วุฒิตรวจ/เพิ่ม
- ยังไม่ทดสอบบนมือถือจริง (รอผู้ก่อตั้งติดตั้ง Android Studio — ขั้นตอนใน `engineering/tooling_setup.md`)
- ผู้ก่อตั้งจะวางไฟล์เดิม (Unity / เดโม HTML / ui_design_prompt) → เทียบกับ ADR-002 และชื่อเหรียญ

## ขั้นต่อไป (เสนอ)
1. แดชบอร์ด: แก้งบรอบ/วันเงินเข้า/ราคามื้อ (stepper), เส้นเวลาวัน, BudgetDeficit, Badge grid (คงแนวคิดเดิม)
2. สุ่มเมนู → สแกน (หลังมี Android)
3. รอผู้ก่อตั้งอนุมัติ: รายการซื้อของ, แจ้งเตือนเช้า, ปิดวันตอนค่ำ
