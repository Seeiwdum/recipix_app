# PHASE 1.5 — UI Refinement Sprint (ทีมคุยกัน หา reference แล้วยกระดับ UI)

> หมายเหตุทีม: brief นี้อ้าง `ADR-002_ui_direction_v2.md` แต่ ADR-002 ถูกใช้ไปแล้ว (BudgetDeficit) จึงบันทึกเป็น `ADR-012_ui_direction_v2.md` แทน และ `docs/ui_design_prompt.md` ยังไม่มีในรีโป จึงใช้เช็กลิสต์ 5.5 จาก MASTER_PROMPT

## 1. สถานการณ์
- Phase 1 จบแล้ว: ระบบดีไซน์ ไอคอน app shell ผ่านเช็กลิสต์ และรันบน localhost ใน VS Code ได้
- ผู้ก่อตั้งดูผลแล้วบอกว่า **UI ดู minimal แล้ว แต่ยัง "ขาดอะไรไปหน่อย"** และ **ไม่อยากให้เหมือน AI slop เกินไป และไม่อยากให้เหมือนโฆษณา**
- ผู้ก่อตั้ง **ไม่ได้บอกว่าขาดอะไร** งานแรกของทีมคือ "วินิจฉัยให้ได้ว่าขาดอะไร" ด้วยหลักฐาน ห้ามเดาแล้วลงมือแต่งเติม
- ผู้ก่อตั้งอนุญาตให้ทีมคุยกันเอง, หา reference เอง หรือใช้ Figma ที่ผู้ก่อตั้งเชื่อมไว้เป็น reference ได้

**เป้าหมาย:** UI ที่ยังสะอาดและมุมมนเหมือนเดิม แต่มีตัวตนเฉพาะของ Recipix อบอุ่นแบบครัว ใช้งานจริง ไม่ตะโกนขายของ และคนดูแล้วไม่คิดว่า "นี่ทำจากเทมเพลต AI"

## 2. ขั้นตอน
- **A — ตรวจสภาพจริง:** ภาพทุกแท็บ/สถานะสำคัญที่ 360/390/430 → `docs/design/shots/before/` (`แท็บ_สถานะ_ความกว้าง.png`); `docs/design/audit.md` จดข้อเท็จจริง ยังไม่ตัดสิน
- **B — Design Critique:** subagents อิสระ (มี่ UX/UI, ดล เกม/ความรู้สึก, วุฒิ+วีน่า อาหาร/ผลิตภัณฑ์, ฎา QA/ผู้ใช้ใหม่, ธนากร ผู้ค้าน slop/โฆษณา) → `docs/design/critique/<บทบาท>.md`; พิมรวมเป็น `_synthesis.md` พร้อมสมมติฐาน "ขาดอะไร" 3-5 ข้อ (signature, ตัวอักษร, ความเป็นครัว, ภาพวัตถุดิบ, น้ำเสียง, ไมโครดีเทล, ความหนาแน่น)
- **C — Reference ≥ 10:** Figma ของผู้ก่อตั้ง (อ่านอย่างเดียว; หาไม่เจอ = คำถาม L3 ตอนรายงาน) + ค้นเว็บ 5 ทิศทาง ทิศทางละ ≥ 2 (แอปตู้เย็น/ซื้อของ, แอปงบประมาณที่ไม่ขู่, สูตรอาหาร/บรรณาธิการอาหาร, เกมจัดของ/ครัว, งานนอกแอป: ฉลาก ป้ายตลาด สมุดบัญชี งานพิมพ์ไทย); สกัดหลักการ ห้ามลอก; บันทึก `docs/design/references.md` รูปแบบ `ที่มา | ทำไมเลือก | หลักการ | สิ่งที่ห้ามเอามา | ใช้กับหน้าไหน`
- **D — Direction v2:** 3 ทิศทาง (ชื่อ, หลักการ 3 ข้อ, signature 1 อย่าง, เปลี่ยนอะไรแต่ละแท็บ, ความเสี่ยง, reference ที่รองรับ) ให้คะแนน 1-5 (เอกลักษณ์ / อาหารไทยชีวิตจริง / สะอาดอ่านง่าย / ไม่เป็นโฆษณา / ทำได้ 60 FPS / สม่ำเสมอกับระบบเดิม); ธนากรตรวจหมวด 4; เลือก 1 (L2) + สำรอง 1 → ADR
- **E — ลงมือ:** tokens ก่อน → signature ที่ศูนย์กลางจุดเดียว ใช้ซ้ำอย่างสุขุม → แท็บตามลำดับ ตู้เย็น → หน้าหลัก → สแกน → สุ่มเมนู → แดชบอร์ด (Badge คงแนวคิดเดิม); ทุกการเปลี่ยนจดใน `docs/design/changelog_ui.md` ตามรอยกลับ reference + ข้อวินิจฉัย ไม่มีเหตุผล = ย้อนกลับ; golden + analyze + test ผ่าน ห้ามทำ logic พัง; ภาพ `after/` ชุดเดียวกับ `before/`
- **F — ตรวจก่อนส่ง:** หมวด 4 ทุกข้อ + 5.5 เดิม; 5-second test ด้วย subagent; อัปเดตเอกสาร commit; รายงาน CP2 พร้อมก่อน/หลัง และทิศทางสำรอง

## 3. ตัวเลือกยกระดับ (เลือกเฉพาะที่ตรงกับผลวินิจฉัย ห้ามใส่ครบ)
ลายเซ็นจากเรื่องจริงของแอป (วันหมดอายุ, ตัวเลขหลัก, ป้ายแขวนของ, กริดชั้นวาง) · ตัวอักษร (ช่วงขนาด/น้ำหนักต่างชัด, ตัวเลขเงิน/แคลอรี่มีวิธีเฉพาะ หน่วยเล็กกว่า tabular, ระยะไทย) · ภาพวัตถุดิบมีบุคลิกคงที่ (กฎเงา มุม เส้น แสง) · สถานะว่าง/ผิดพลาด/โหลดมีน้ำเสียงครัว · ไมโครดีเทล (เส้นแบ่ง หน่วย วันที่ แฮปติก ทรานซิชันสอดคล้อง) · ความหนาแน่นที่มีประโยชน์ · การเคลื่อนไหวน้อยแต่ดี ห้ามวนไม่จบ

## 4. เช็กลิสต์ "AI slop / โฆษณา" (ธนากรใช้ค้าน)
**อาการที่ต้องไม่มี:** การ์ดมุมมนเหมือนกันหมดเรียงซ้ำเป็นกริด · สูตร "ตัวเลขใหญ่กลาง + ข้อความรอง + ปุ่มเต็มความกว้าง" ทุกหน้า · ชิป/ป้ายพาสเทลเกลื่อน สถิติเป็นกล่อง กราฟตกแต่ง · ไอคอนเส้นทั่วไปแบบชุดสำเร็จรูป · ข้อความเป็นมิตรแบบเทมเพลต · ภาษาเร่งเร้า/ขายของ/ขู่ · ความเคลื่อนไหวที่มีไว้โชว์
**แบบทดสอบ (บันทึกผล):** 1) Swap test 2) Remove test 3) 5-second test 4) Reference test 5) Ad test

## 5. ข้อห้ามและขอบเขต
คงกฎ 5.1 ทั้งหมด (ห้าม Emoji, ห้าม gradient/glow/blur ตกแต่ง, ห้ามแอนิเมชันวนไม่จบ ฯลฯ) · ห้ามเปลี่ยนกติกาธุรกิจ/สถาปัตยกรรม (แตะเฉพาะ presentation + tokens + assets) · ห้ามลอกงาน/ฟอนต์ลิขสิทธิ์ ห้ามใช้ของที่ต้องซื้อโดยไม่ถาม (L3) · Figma อ่านอย่างเดียว · ห้ามหยุดรอผู้ก่อตั้ง (L3 รวมไว้ตอนรายงาน) · 60 FPS, analyze/test ผ่านก่อน commit

## 6. Definition of Done
`docs/design/{audit.md, critique/*.md + _synthesis.md, references.md (≥10), direction_v2.md, changelog_ui.md, shots/before, shots/after}` + ADR ทิศทาง + โค้ด (tokens, assets, presentation) + golden อัปเดต + analyze/test ผ่าน + เอกสารอัปเดต + commit + รายงาน CP2 (ก่อน/หลัง, ทิศทางที่เลือก, สำรอง, สิ่งที่ควรลองด้วยมือ, คำถาม L3)
