# ADR-008: บันทึกค่ากิน และแผนกินถึงวันเงินเข้า

- **ระดับ:** ฟีเจอร์ใหม่อนุมัติโดยผู้ก่อตั้ง (L3, 2026-10-16) — รายละเอียดกติกาด้านล่างเป็น L2
- **ยังไม่ทำ (ผู้ก่อตั้งให้รอ):** รายการซื้อของ, แจ้งเตือนเช้า, ปิดวันตอนค่ำ

## บันทึกค่ากิน (`recipix_core` `BudgetLedger`)
1. ผู้ใช้ตั้ง **งบทั้งรอบเงินเดือน** (`periodBudget`) แล้วบันทึกรายจ่าย; "งบเหลือ" = งบรอบ − รายจ่ายในรอบ (ติดลบได้ = ใช้เกิน)
2. **รอบ** เริ่มวันเงินเข้าครั้งล่าสุด (ไม่ตั้งวันเงินเข้า = วันที่ 1) ถึงวันก่อนเงินเข้าครั้งถัดไป — รายจ่ายนอกรอบไม่นับ
3. **งบวันนี้คงที่ตั้งแต่เช้า** = งบเหลือตอนเริ่มวัน ÷ วันถึงเงินเข้า (ไม่ติดลบ) — จ่ายระหว่างวันไม่ทำให้งบวันนี้หด แต่แสดงเป็น "ใช้ไป x · เหลือ y" หรือ "เกินงบวันนี้ z"
4. `SurvivalEngine` ใช้ "งบเหลือตอนนี้" เป็น `foodBudget` → ยอดขาด (ADR-002) ขยับทันทีที่บันทึก
5. หมวด: กินข้างนอก (นับเป็น 1 มื้อในแผน) / ซื้อของเข้าบ้าน / อื่นๆ; ปุ่มจำนวนลัดเป็นข้อมูลตั้งค่า (`quickAmounts`) ไม่ฮาร์ดโค้ดในหน้าจอ
6. ข้อมูลตัวอย่าง: กินข้างนอกวันละ 180-200 บาทตั้งแต่ต้นเดือนถึงเมื่อวาน และงบรอบที่ทำให้เหลือ 1,600 บาทวันนี้ — แทนด้วยข้อมูลจริงเมื่อมี persistence

## แผนกินถึงวันเงินเข้า (`recipix_core` `MealPlanner`)
1. ช่องมื้อ = มื้อต่อวัน (ตั้งค่า, ตั้งต้น 3) × ทุกวันถึงวันก่อนเงินเข้า; มื้อวันนี้ที่ทำกินแล้ว + กินข้างนอกที่บันทึกแล้ว ไม่วางแผนซ้ำ
2. **Greedy, deterministic:** แต่ละมื้อเลือกเมนูที่ทำได้ครบจากของในตู้ (จำลองตัดของตามปริมาณด้วย `InventoryService` ณ วันนั้น ของหมดอายุไม่ใช้) ให้คะแนน Σ 1/(วันเหลือ+1) ของวัตถุดิบที่ใช้ — ของใกล้หมดก่อน; หักคะแนนเมนูซ้ำมื้อติดกัน (−10) และซ้ำในวันเดียว (−1); เสมอกันเรียงตาม id
3. ทำไม่ได้ = ซื้อกิน ราคา `mealOutPrice`
4. **ยอดขาดตามแผน** = max(0, ค่าซื้อกินทั้งหมด − งบเหลือ) — เป็น "สถานการณ์ตามแผน" แยกจากยอดขาดตามแคลอรี่ (ADR-002) ที่หน้าหลัก ข้อความจึงขึ้นต้นว่า "ตามแผนนี้"
5. **จะเสียก่อนได้ใช้:** ของที่สูตรใดสูตรหนึ่งใช้ได้ แต่ยังเหลือและหมดอายุก่อนเงินเข้า — ของที่ไม่มีสูตรใช้ (นม โยเกิร์ต) ถือว่ากินเปล่าๆ ไม่นับว่าเสีย
6. ไม่รู้จักของปริศนา ไม่วางแผนให้; ไม่คิดเครื่องปรุงพื้นฐาน (น้ำมัน เกลือ น้ำตาล)

## ทำกิน (ปิดวงจร)
- แตะมื้อในแผน/มื้อถัดไป → sheet แสดงของที่จะใช้ → "ทำแล้ว" ตัดของจริงจากตู้ (FEFO ตามปริมาณ), ของหมดออกจากชั้น, บันทึกใน `cooked` (ใช้ต่อกับ badge "ทำกินเองบ่อย" ภายหลัง), toast เลิกทำ (คืนทั้งตู้ถ้ายังไม่มีอะไรเปลี่ยน)

## ผลที่ตามมา
- ความแม่นของแผนขึ้นกับฐานสูตร (ตอนนี้ 10 เมนู) — ยิ่งมีสูตรมาก ยิ่งทำเองได้มากมื้อ
- ข้อมูลยังไม่บันทึกถาวร: ปิดแอปแล้วรายจ่ายหาย → persistence ควรมาก่อนฟีเจอร์ถัดไป
