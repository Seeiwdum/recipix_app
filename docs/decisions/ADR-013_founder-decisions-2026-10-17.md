# ADR-013 — คำตัดสินของผู้ก่อตั้งหลัง CP2 (2026-10-17)

## บริบท
รายงาน CP2 ของ PHASE 1.5 ถามคำถาม L3 สามข้อ ผู้ก่อตั้ง (NAMOE) ตอบในแชตว่า
"อนุมัติทั้งสองข้อ: หัวข้อเป็นมื้อ และชื่อแท็บสมุดค่ากิน ทำปุ่มเพิ่มของเข้าตู้เองต่อเลย"

## การตัดสินใจ
1. **ตัวเลขหลักหน้าแรกเป็น "มื้อ"**: "ทำกินเองจากของในตู้ได้อีก x มื้อ" ใช้ตัวเลขเดียวกับแผนกิน (`MealPlanner.homeMeals`) แทน "อยู่ได้อีก x วัน" จาก kcal ในสเปก 5.3 ส่วน `SurvivalEngine` ยังคำนวณเหมือนเดิม (ยอดขาดยังใช้)
2. **ชื่อแท็บ "สมุดค่ากิน"** แทน "แดชบอร์ด"
3. **เพิ่มของเข้าตู้เองด้วยมือ** (ฟีเจอร์ใหม่ ไม่ต้องรอแท็บสแกน):
   - ปุ่ม "เพิ่มของ" ที่หัวตะกร้าในแท็บตู้เย็น เปิด sheet รายการวัตถุดิบจากแคตตาล็อก
   - แตะ 1 ครั้งเท่ากับเพิ่ม 1 ชิ้นลงตะกร้า ใช้ปริมาณตั้งต้นของชนิดนั้น วันหมดอายุนับจากวันนี้ตาม `shelfLifeDays`
   - ผู้ใช้ลากของจากตะกร้าขึ้นชั้นเอง ซึ่งเป็นเกมจัดตู้เดิม
   - กด "เอาออก" ได้ทันทีถ้าแตะผิด การเอาออกแบบนี้ไม่บันทึกเป็น "ใช้แล้ว/ทิ้ง" จึงไม่กระทบเหรียญ
   - หน้าหลักตอนตู้ว่างมีลิงก์ไปแท็บตู้เย็น

## ไม่ทำในรอบนี้ (สงสัย = ไม่เพิ่ม)
- แก้ปริมาณหรือวันหมดอายุตอนเพิ่ม: ค่าตั้งต้นพอสำหรับเริ่ม ทำเมื่อมีหลักฐานว่าต้องใช้
- ช่องค้นหา: แคตตาล็อกมี 18 ชนิด เห็นได้ในจอเดียว
- เพิ่มของที่ไม่อยู่ในแคตตาล็อก (ชื่ออิสระ): ต้องคิดเรื่อง kcal และภาพ ต้องคุยกับวุฒิก่อน

## ผลกระทบ
- `FridgeController.addFromCatalog` / `removeAdded` บันทึกผ่าน persistence เดิม (ADR-009) ไม่ต้องเปลี่ยน schema
- คำถาม L3 ข้อ 2, 3 และ 7 ใน `handoff.md` ปิดแล้ว
