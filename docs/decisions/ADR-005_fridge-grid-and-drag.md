# ADR-005: แบบจำลองกริดตู้เย็นและระบบลาก-วาง

- **ระดับ:** L2

## การตัดสินใจ
1. **กริดอยู่ฝั่งแอป ไม่ใช่ core** (`lib/features/fridge/domain/fridge_layout.dart`, Dart ล้วน): ตำแหน่งบนชั้นเป็นเรื่องการแสดงผล/เกม ไม่กระทบกติกาธุรกิจ core เก็บแค่ `StorageZone` ซึ่งอัปเดตเมื่อย้ายช่อง
2. **ผังตู้มาตรฐาน 25 ช่อง:** ช่องแช่แข็งเต็มความกว้าง 5 ช่อง / ชั้นบน-กลาง-ล่าง 4 ช่อง / ลิ้นชักผัก 4 ช่อง / ชั้นประตู 1x4; ของกว้าง 1 หรือ 2 ช่อง (กำหนดใน `assets/data/ingredients.json` ฟิลด์ `width`); ของปริศนากว้าง 1
3. **ไม่จำกัดโซน:** วางของชนิดไหนช่องไหนก็ได้ (เหมือนตู้จริง) ยกเว้นข้อจำกัดทางกายภาพ (ของกว้าง 2 ใส่ชั้นประตูไม่ได้, ช่องเต็ม) — กฎโซนที่เข้มกว่านี้เป็นการเปลี่ยนเกม ต้องตัดสินแยก
4. **ใช้แล้ว/ทิ้ง:** ของทางขวาในแถวเดียวกันเลื่อนซ้ายอุดช่อง (`closeGap`) แต่ช่องว่างที่ผู้เล่นตั้งใจเว้นที่อื่นไม่ถูกแตะ; ย้ายของไม่ทำ compaction
5. **Undo:** เก็บ arrangement ก่อนลบ ถ้ายังไม่มีอะไรเปลี่ยนให้คืนทั้งชุด (เพื่อนบ้านกลับที่เดิม) ถ้าเปลี่ยนแล้วคืนช่องเดิมถ้าว่าง ไม่งั้นลงตะกร้า
6. **ลาก-วางเขียนเอง** แทน `Draggable/DragTarget`: ต้องการ spring snap เข้าช่องและเด้งกลับที่เดิมเมื่อวางไม่ได้ ซึ่ง `Draggable` ไม่มี; ทุกอย่างอยู่ใน Stack เดียว (`FridgeGeometry`) จึงไม่ต้องใช้ Overlay
   - spring: `withDampingRatio(stiffness 520, ratio 0.8)` overshoot ~1.5% (งบ 6%)
   - `DragStartBehavior.down` — ไม่งั้นจุดจับคลาดไปตาม touch slop (เจอเป็นบั๊กระหว่างทำ)
   - item ต้นทางต้องคงอยู่ใน tree (ซ่อนด้วย Opacity) ไม่งั้น pan recognizer ถูก dispose กลางทาง (เจอเป็นบั๊กระหว่างทำ)
7. **ทางที่ไม่ต้องลาก:** sheet ของในตะกร้ามีปุ่ม "จัดเข้าตู้ให้" (`autoPlace` เลือกโซนปกติก่อน) และของบนชั้นมี "ย้ายไปตะกร้า" — สำหรับผู้ใช้ screen reader และคนที่ไม่อยากลาก
8. **ข้อมูลตัวอย่างอยู่ในหน่วยความจำ** (`sample_fridge.dart`) จนกว่าจะมี persistence (Phase 3); catalog โหลดจาก asset ใน `main()` แล้ว inject ผ่าน `catalogProvider`

## ผลที่ตามมา
- เพิ่มชนิดตู้อื่น (ตู้ประตูคู่ ฯลฯ) ได้โดยเพิ่ม compartment + geometry
- ค่าแคลอรี่/อายุใน catalog เป็นค่าประมาณรอบแรก ต้องให้วุฒิตรวจแหล่งอ้างอิงก่อนปล่อย
