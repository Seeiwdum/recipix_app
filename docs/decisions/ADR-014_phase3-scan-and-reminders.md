# ADR-014 — ขอบเขต Phase 3: สแกนบาร์โค้ด + แจ้งเตือนของใกล้หมดอายุ

## บริบท
- สเปก (MASTER_PROMPT §P2 แท็บสแกน, Phase 3) อยากได้ 3 โหมด: วัตถุดิบ / บาร์โค้ด / ใบเสร็จ
- ADR-007 กำหนดให้ใช้ ML Kit ในเครื่อง ไม่ส่งภาพออกนอกเครื่อง และไม่มีค่าใช้จ่าย
- ตรวจ 2026-10-17 แล้วพบว่า:
  - ML Kit Text Recognition v2 รองรับ Latin, จีน, เทวนาครี, ญี่ปุ่น, เกาหลี **ไม่มีไทย** (developers.google.com/ml-kit/vision/text-recognition/v2/languages) จึงอ่านใบเสร็จไทยในเครื่องไม่ได้
  - ML Kit image labeling รู้แค่คำกว้าง ("vegetable", "meat") แยกหมูกับไก่ไม่ได้
  - บาร์โค้ดอ่านในเครื่องได้ (`mobile_scanner` 7.4.2 ใช้ ML Kit barcode แบบ bundled บน Android +3–10 MB และรองรับ web) แต่ตัวเลขบาร์โค้ดต้องมีฐานข้อมูลถึงจะรู้ว่าเป็นสินค้าอะไร

## คำตัดสินของผู้ก่อตั้ง (L3, 2026-10-17)
| เรื่อง | ตัดสิน |
|---|---|
| ใบเสร็จ | ข้ามไปก่อน กลับมาทำเมื่อมี OCR ไทยในเครื่องที่ใช้ได้ |
| บาร์โค้ด | ค้นออนไลน์ + จำไว้ในเครื่อง |
| แจ้งเตือนของใกล้หมดอายุ | ทำ แบบเปิดเอง (opt-in) วันละครั้ง |
| ถ่ายรูปวัตถุดิบ | ยังไม่ทำ |

## การออกแบบ (L2)
### สแกนบาร์โค้ด
1. กล้องอ่านบาร์โค้ด (`mobile_scanner`)
2. ดูความจำในเครื่องก่อน (`recipix.barcodes.v1`: barcode → catalog key) ถ้าเคยสแกนแล้วไม่ต้องออกเน็ต
3. ถ้ายังไม่รู้จัก ส่ง **เฉพาะตัวเลขบาร์โค้ด** ไป Open Food Facts API v3
   - `GET https://world.openfoodfacts.org/api/v3/product/<code>?fields=product_name,product_name_th,brands`
   - ไม่ต้องมีบัญชี จำกัด 15 ครั้งต่อนาทีต่อ IP และต้องส่ง User-Agent ของแอป
   - ใช้ `http` 1.6.0
4. ได้ชื่อสินค้า (ถ้ามี) แสดงให้ผู้ใช้ดู แล้วผู้ใช้เลือกชนิดวัตถุดิบจากแคตตาล็อก จากนั้นแอปจำคู่ barcode → ชนิด ไว้ในเครื่อง
5. ของเข้า **ตะกร้า** เหมือนการเพิ่มด้วยมือ (ADR-013) ผู้ใช้ลากขึ้นชั้นเอง
6. ไม่มีเน็ต / API ล่ม / ไม่พบสินค้า: ผู้ใช้ยังเลือกชนิดเองได้ แอปไม่ติดตัน

ไม่ส่งข้อมูลส่วนบุคคลออกนอกเครื่อง: ตัวเลขบาร์โค้ดของสินค้าทั่วไปไม่ใช่ข้อมูลส่วนบุคคล User-Agent ใช้ลิงก์ repo แทนอีเมล

### แจ้งเตือน (ทำเป็นขั้นถัดไปใน Phase 3)
- วันละ 1 ครั้งตามเวลาที่ผู้ใช้ตั้ง (ค่าเริ่มต้น 08:00) บอกว่าของอะไรหมดอายุวันนี้/พรุ่งนี้
- ปิดอยู่จนกว่าผู้ใช้จะเปิด ถ้าไม่มีของให้เตือนก็ไม่ส่ง
- `flutter_local_notifications` 22.3.2: ต้องเปิด core library desugaring และขอสิทธิ์ POST_NOTIFICATIONS ตอนรันบน Android 13+
- ADR แยกตอนลงมือ ถ้าโครงต่างจากนี้

## ทางเลือกที่ไม่เลือก
- **OCR บนคลาวด์** (เช่น Google Cloud Vision): อ่านไทยได้ แต่ภาพออกนอกเครื่องและมีค่าใช้จ่าย ขัด ADR-007
- **Tesseract ไทยในเครื่อง:** แอปใหญ่ขึ้นและน่าจะแม่นต่ำกับใบเสร็จกระดาษความร้อน
- **ฐานบาร์โค้ดออฟไลน์ล้วน:** ไม่มีแหล่งข้อมูลไทยที่หาได้เอง

## ผลกระทบ
- แท็บสแกนตามสเปกจะมีโหมดเดียว (บาร์โค้ด) และทางลัดไป "เพิ่มของเอง" (ADR-013)
- เพิ่ม dependency: `mobile_scanner`, `http` (และ `flutter_local_notifications` ตอนทำแจ้งเตือน)
- Android ต้องขอสิทธิ์กล้อง; ทดสอบกล้องจริงได้ผ่าน APK จาก GitHub Actions เท่านั้น (เครื่องพัฒนาไม่มี Android SDK)
- ADR-007 แถว "จำของจากกล้อง" ถูกปรับขอบเขตโดย ADR นี้
