# ADR-010: แดชบอร์ด, แก้งบได้ และเหรียญจากประวัติ

- **ระดับ:** L2 (สเปกแท็บอยู่ใน MASTER_PROMPT 5.3 แล้ว)

## งบแก้ได้
- งบรอบเป็นตัวเลขใหญ่ + stepper (ทีละ 100 บาท; กดค้าง = ซ้ำ แล้วเร่งเป็น x5 หลัง ~1 วินาที) แทนสไลเดอร์ไล่สีของเดโม
- วันเงินเข้า stepper: "ใช้ถึงสิ้นเดือน" → 1 → … → 31; ราคาซื้อกิน stepper ทีละ 5 บาท (ขั้นต่ำ 1 บาท)
- ขอบเขตกันพิมพ์พลาด: งบ 0 – 200,000 บาท, ราคา 1 – 2,000 บาท (ไม่ใช่กติกาธุรกิจ)
- เปลี่ยนวันเงินเข้า = รอบเปลี่ยน → รายจ่ายนอกรอบใหม่ไม่ถูกนับ และงบรอบหมายถึงรอบใหม่ทันที

## เหรียญ = เล่นประวัติซ้ำ (ไม่มี state ของเหรียญเก็บแยก)
- ประวัติที่บันทึก: ใช้แล้ว/ทิ้ง (`activity`, พร้อมวันเหลือตอนนั้น), ทำกิน (`cooked`, พร้อมจำนวนของเร่งด่วนที่ใช้), รายจ่าย
- `badgeProgressProvider` ไล่ทีละวันจากวันแรกที่มีข้อมูลถึงวันนี้: ส่งเหตุการณ์ของวันนั้นเข้า `AchievementManager` (core) แล้วถ้าเป็นวันที่ผ่านไปแล้ว ส่ง `DayClosed` (จ่ายจริงวันนั้น vs งบวันนั้นตอนเช้า)
- ผลเหมือนเดิมเสมอสำหรับประวัติเดิม; undo = ลบรายการล่าสุดออกจากประวัติ → เหรียญถอยตาม
- **วันก่อนเริ่มติดตาม** (`trackingSince` = วันเปิดแอปครั้งแรก): ไม่รู้ว่าทิ้งอะไรไหม → `discardedCount = null` → เหรียญ "ไม่ทิ้งของ 7 วัน" ข้ามวันนั้น (core: `DayClosed.discardedCount` เป็น nullable)
- **ข้อจำกัดที่รู้:** วันที่ไม่ได้บันทึกรายจ่ายนับเป็น "อยู่ในงบ" สำหรับเหรียญประหยัดงบ (จ่าย 0 ≤ งบ) — ถ้าผู้ใช้ลืมบันทึกจะได้ streak ง่ายขึ้น; แก้ได้ด้วย "ปิดวันตอนค่ำ" (รอผู้ก่อตั้งอนุมัติ) → ตอนนั้นค่อยนับเฉพาะวันที่ปิดแล้ว
- เปลี่ยนงบรอบย้อนหลังเปลี่ยนงบรายวันในอดีต → ผลเหรียญประหยัดงบอาจเปลี่ยนตาม (ยอมรับ: งบคือข้อมูลที่ผู้ใช้ตั้ง)
- คงชื่อ/แนวคิดเหรียญเดิม 5 อัน ไอคอน SVG: นาฬิกา (ใกล้หมดอายุ), เหรียญ (ประหยัดงบ), กระทะ (ทำกินเอง), ใบไม้ (ไม่ทิ้งของ), สแกน (สแกนครั้งแรก — ยังได้ไม่ได้จนกว่าจะมีแท็บสแกน)

## ส่วนอื่นของแดชบอร์ด
- เส้นเวลารอบ: 1 แท่งต่อวัน — อยู่ในงบ (เขียว) / เกินงบ (แดง) / ไม่ได้บันทึก (เทาอ่อน) / วันนี้ (กรอบเข้ม) / อนาคต (เส้นขอบ)
- "เงินที่เหลือซื้ออะไรได้": มื้อ = งบเหลือ ÷ ราคามื้อ (ปัดลง), วัน = งบเหลือ ÷ (ราคา × มื้อ/วัน), งบต่อวันถึงเงินเข้า
- "เมนูที่ทำบ่อย": 5 อันดับจากประวัติทำกิน แท่งบางสีเดียว
