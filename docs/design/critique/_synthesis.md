## สิ่งที่ทุกคนบอกให้ **คงไว้**
กริดตู้เย็นจริง + ป้ายวันบนของ · ภาพวัตถุดิบ flat บนพื้นเบจ · พาเลตครีม/เขียวเดียว ไม่มีเงา/ไล่สี · ตัวเลข tabular · ภาษาสถานะ "ควรใช้วันนี้ / เหลือ 1 วัน" · สุ่มเมนูผ่าน 5-second test · sheet สั่งข้างนอกผูกเงินกับการตัดสินใจ · สปริงตู้เย็นและวงล้อหยุดทีละแกน · reduce motion

## สมมติฐาน "ขาดอะไร" (เรียงตามหลักฐาน)

1. **ขาด "ภาษาเดียวของตัวเลข" ที่น่าเชื่อ** — แอปนี้คือเครื่องคิดเลขค่ากิน แต่ตัวเลข/หน่วยจัดคนละแบบ ซ้ำกันคนละที่ และสองยอดขาดไม่บอกที่มา → ความรู้สึก "มีอะไรแปลกๆ" (ประเด็น 4, 1) *[ข้อ 3 ของ brief: ตัวอักษร + ตัวเลข]*
2. **ขาดโครงสร้างที่เป็นของ Recipix นอกตู้เย็น** — "กระดาษครัว" มีแค่สี โครงยังเป็นการ์ด SaaS; ข้อมูลควรวางเป็น "บรรทัด" แบบสมุด/ใบเสร็จมากกว่ากล่อง (ประเด็น 3, 10) *[signature]*
3. **ขาดความหมายของสี** — แดงถูกใช้เน้นทุกเรื่อง จึงไม่เหลือความหมาย "ต้องทำวันนี้" และทำให้ทั้งแอปอ่านเป็นคำตัดสิน (ประเด็น 1)
4. **ขาดความจริงในสถานะว่าง/ครั้งแรก** — ข้อความที่มั่นใจแต่ผิดคือสัญญาณ "AI ทำ" ที่แรงที่สุด (ประเด็น 2, 7)
5. **ขาดมิติและบุคลิกของวัตถุ** — ของในตู้ไม่มีน้ำหนักตอนหยิบ, โซนไม่มีวัสดุ, เหรียญไม่ใช่ของที่อยากสะสม, จานไม่มีภาพ (ประเด็น 5, 6, 8)

## ข้อที่อยู่นอกขอบเขต sprint (ห้ามแตะกติกาธุรกิจ) — จดไว้เป็นงานต่อ
- แผนกินวนเมนูเดิมทุกวัน (กติกา planner, ADR-008) → L2 รอบหน้า
- นับพลังงานของเครื่องปรุง (น้ำปลา) และขาดวัตถุดิบบ้านไทย (ข้าวสาร มาม่า ลูกชิ้น ซอสหอยนางรม), กระเทียมถูกนับเป็น "ของที่ขาด" → ข้อมูล/กติกา วุฒิ รอบหน้า
- ตัวเลขหลัก "อยู่ได้อีก x วัน" จาก kcal: วุฒิ+วีน่าเสนอเปลี่ยนเป็น "มื้อ" แต่สเปก 5.3 ของผู้ก่อตั้งกำหนดตัวเลขนี้ไว้ → **คำถาม L3**
- เปลี่ยนชื่อแท็บ "แดชบอร์ด" เป็น "สมุดค่ากิน" (ชื่อแท็บอยู่ในสเปกผู้ก่อตั้ง) → **คำถาม L3**
- ภาพจานอาหาร (flat) สำหรับมื้อถัดไป/ผลสุ่ม → ทำได้ (assets) แต่ต้องวาด 10+ ภาพให้คุณภาพเท่าวัตถุดิบ → งานต่อแยก ไม่ยัดใน sprint นี้
